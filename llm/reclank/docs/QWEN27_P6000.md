# Qwen3.8-27B on a Quadro P6000 (Pascal): the planar rows

The model: `byteshape/Qwen3.8-27B-GGUF`, file `Qwen3.8-27B-IQ4_XS-3.84bpw.gguf` (13.1 GB; the label is
only a size class: ShapeLearn picks a type for each tensor). The drafter: the DFlash 2 GGUF
`Qwen3.8-27B-DFlash2-Q4_K_M.gguf` (`models/qwen/dflash2.py`, `--drafter`). The machine: a Xeon W-2133 and a
P6000 (GP102, sm_61, 24 GB, dp4a, no tensor cores), its power capped at 175 W for the numbers here.

    scripts/serve_qwen27.sh -d          # the server with DFlash 2 on 127.0.0.1:8080 (MODEL, DRAFTER, CTX, ...)

## The file

The 64 layers (48 Gated DeltaNet, 16 full attention with 24 query heads on 4 key heads, a dense SwiGLU MLP
each) and the MTP layer. The bytes of each type:

| type | GB | where |
|---|---|---|
| IQ4_XS | 3.60 | the embeddings, many MLP and attention matrices, eh_proj |
| IQ3_S | 3.56 | MLP, attn_qkv, ssm_out, ... |
| IQ3_XXS | 2.46 | MLP (the down matrices most) |
| Q4_K | 1.66 | attn_qkv, attn_q, ... |
| Q6_K | 1.08 | the head (1.04), attn_v |
| Q3_K | 0.38 | some gates, attn_qkv of layer 0 |
| Q5_K, IQ2_XXS, IQ2_XS, Q8_0, Q2_K | 0.32 | |

The file has no tokenizer.json beside it: `formats/gguf.py` `_BPE_PRE["qwen35"]` (llama.cpp's pattern, NFC)
makes the tokenizer from the GGUF's vocabulary (the same ids as Qwen3.6's tokenizer.json on the checks).

## The planar rows (GPUs without the tensor cores)

The kernels of the ggml blocks (`kernels/quant/iq.cuh`: `k_kq_ft` for a step and a small group, the dp4a
tiles for a prompt) read blocks of 98, 110, 74 ... bytes, only 2-aligned: halfword loads. On Pascal
`QwenGPU._pr_on` (a dense model with i-quants, a GPU with dp4a and no tensor cores; `RECLANK_GPU_PR`=0 / 1
/ auto) gives each matrix rows of the same bits in planes, so each part of 32 values is aligned loads
(`formats/pr_rows.py` `to_rows`; checked bit for bit against the GGUF decoder). Their ids are their own,
so the kernels of the ggml ids stay as they are on the other GPUs:

| GGUF type | GPU type | rows |
|---|---|---|
| IQ4_XS | KQ_PR_IQ4X 107 | the blocks as they are (136 bytes, 8-aligned) |
| IQ3_S | KQ_PR_IQ3S 101 | index bytes, signs, 9th bits, scales, d |
| IQ3_XXS | KQ_PR_IQ3X 102 | index bytes, sign/scale words, d |
| Q3_K | KQ_PR_Q3K 103 | 2-bit codes, inverted high bits, int8 scales, d |
| IQ2_XS | KQ_PR_IQ2S 104 | codes, scales, d |
| IQ2_XXS | KQ_PR_IQ2X 105 | KQ_IQ2R's rows (Bolt's form) |
| Q6_K (the head) | KQ_PR_Q6K 106 | low 4 bits, high 2 bits, int8 scales, d |
| Q2_K | float32 | (ssm_beta: 48 rows) |

- Steps and groups of up to 16 tokens (`kernels/quant/pr.cu`, `pr_mv.cuh`, `pr_fmt.cuh`): `k_pr_mv`, a
  kernel for each type, token count (1-8) and R rows a warp (1 for a step, 4 for a group:
  `RECLANK_GPU_PR_R`; each token's x read once for 4 rows), a launch for each matrix of a GP_KQ_MULTI.
  `RECLANK_GPU_PR_ALL` (`_pr_on` sets it) takes the Q4_K, Q5_K, Q6_K, Q8_0 records there too (with 0, those
  on `k_kq_ft`: a step 57.0 ms, a group of 8 112.5, against 55.9 and 100.9). The IQ3 grids in shared
  memory with the signs by arithmetic. A token of a group gets the bits of a step.
- The head: the Q6_K head in KQ_PR_Q6K rows on `k_pr_mv` (int8 x), through the head's program
  (`_kq_head`; the DFlash 2 drafter's head too). `RECLANK_GPU_PR_HEAD=0` keeps master's Q6R head
  (`k_q6r_head`, float x): a step 58.4 ms, a group of 8 105.8.
- Prompts (groups over 16): `k_pr_gemm` (`pr_mv.cuh`): a tile of 64 tokens by 128 rows; each step of 128
  columns decodes all its parts at once (from global memory) to int8 words in shared memory, then one sync
  and the dp4a of the 4 parts. `RECLANK_GPU_PR_GEMM=0`: the float tiles of `k_kq_gemm` (a check).
- Attention: `k_attn_fdq` takes 6 query heads a key head (24 by 4; `k_attn_part` scheduled 256 chunks of
  36 KB of shared memory each: 126 us a layer at 60 keys).

### A race in the runtime (all models)

`rc_gpu_run` copied the parameters of a run from a pinned buffer (`henv`) with an async copy: the copy
reads it when the stream gets there, so a second run of the same program queued before the first ran
overwrote them (the first took the second's position). Hidden by the engines that read the logits after
each step. Now each run waits for the copy of the run before (`gg_env_free`, an event): the host stays one
run ahead. Seen here as 600 steps drifting from the reference (KL 1.26e-2 at the last row, 2.5e-3 after).

## The checks

The GPU against reclank's NumPy model on the same file (every matrix dequantized as used, no float copies):
24 rows of a chat prompt as steps: argmax 24/24, KL mean 4.3e-5; a 600-token prompt, its last 4 rows from
the prompt's groups: KL 0.6e-3 to 2.5e-3; 600 single steps: 2.5e-3 (the int8 x of the products).
`scripts/check_dflash2.py`: the drafter's context, hidden states and candidates against its NumPy
reference, and its greedy replies the same tokens as plain: PASS.

## The rates (P6000 at 175 W)

| | master (the ggml blocks) | the planar rows |
|---|---|---|
| a step | 75.8 ms | 55.9 ms |
| a verify group of 8 | 187.6 ms | 100.9 ms |
| prompts of 1K, 4K | 60, 114 tok/s | 207, 209 tok/s |
| check_dflash2.py (btree, story, summary): plain | 12.6 tok/s | 17.2 tok/s |
| DFlash 2, stop 0 / 0.5 | 16.4 / 18.5 tok/s | 30.5 / 32.5 tok/s |
| a round's drafts | 29-32 ms | 16-19 ms |

DFlash 2 on short prompts without thinking (greedy, the same tokens as plain): code 61.7 / 60.1 tok/s
(stop 0 / 0.5; 7.3 tokens a round), chat 26.9 / 29.1. The power cap: at 200 and 250 W the step is 1-2%
faster and the prompts 3-4% (never power-limited there: 1657 MHz); at 150 W about 7% slower than 200 W,
with about 20% more tokens a joule. The P6000 at 150 W streams 403 GB/s with a light kernel; under 2
integer instructions a byte are free, 4 a byte gives 311 GB/s.

The kernels' rates on real rows (a standalone bench of `pr_mv.cuh`), one token: IQ4_XS 334-362 GB/s, Q4_K
293-335, Q3_K 335, IQ3_XXS 245-262, IQ3_S 205-251, Q5_K 243, Q6_K 150, IQ2_XXS 136; 8 tokens (R 4): IQ4_XS
216-280, Q4_K 168-179, IQ3 125-160.
